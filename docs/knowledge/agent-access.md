## 需要的权限

智能助手菜单的权限字符是 agent:chat:use，智能助手的所有接口都要求这个权限。
超级管理员（userId=1）拥有全部权限；其他用户能否使用，取决于他们实际被分配的角色是否被授予了这个菜单。
开通方式按实际的角色配置，不同用户的角色不同，排查某个用户时要查询该用户的实时角色和权限。

## 排查顺序

1. 用户账号状态：账号被停用时无法登录（登录提示"用户已封禁，请联系管理员"）。
2. 用户的角色：用户至少要有一个角色被授予了"智能助手"菜单。
3. 角色状态：停用的角色不加载任何权限，它关联的菜单也不会显示。
4. 菜单状态：菜单本身被停用时，任何人（包括超级管理员）都看不到它。
5. 是否重新登录：见下一节。

## 改了授权之后为什么还不生效

左侧菜单在每次加载页面时按数据库里的角色和菜单重新查询；但接口权限取自登录时写入 Redis 的登录态。
所以给角色授权后，如果用户没有重新登录，可能出现"菜单已经出现，但发消息提示没有权限，请联系管理员授权"的情况；
撤销授权后，已登录的会话在重新登录前也可能仍然保留旧权限。数据库里的配置不等于用户当前会话已经生效，
需要让该用户退出后重新登录。

## 助手如何帮忙确认

回答某个账号为什么看不到智能助手时，助手应查询该用户的状态，并由服务端判断该用户的实际角色是否具备
agent:chat:use，不能只根据本文档推断，也不能拿其他角色的配置代替该用户的角色。
查询结果反映的是数据库配置，不代表该用户当前登录会话里的权限。
